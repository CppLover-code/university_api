Сейчас - SessionAuthentication через admin login.

А будет: Bearer Token Authentication.

Как работает JWT
1. Login
Пользователь отправляет:
{
    "username": "teacher1",
    "password": "12345678Aa"
}

2. Backend выдает token
{
    "access": "eyJhbGc...",
    "refresh": "eyJhbGc..."
}
3. Frontend отправляет token в headers:

Authorization: Bearer TOKEN
Backend понимает:

✅ кто пользователь
✅ какая роль
✅ авторизован ли он

Внутри токена хранится:

✅ user_id
✅ expiration time
✅ token type

Performance - как сделать API быстрым и безопасным

✅ Pagination
✅ Throttling
✅ Caching theory
✅ Redis theory

Pagination(Пагинация) - выдача информации частями, например, 10 объектов на 
одну страницу.
Для чего? - чтобы не занружать сразу все объекты, иначе если API отдаст ВСЕХ сразу:
❌ медленно
❌ много памяти
❌ огромный JSON
Поэтому backend делит данные на страницы.

******************************************************************
Throttling - это защита API от:

✅ спама
✅ DDOS-like запросов
✅ перегрузки сервера

Без throttling:

❌ сервер умрет
❌ база перегрузится
❌ API станет медленным

Поэтому backend ограничивает количество запросов! Это называется: Rate Limiting
или: Throttling

******************************************************************
Caching + Redis Theory

** Caching (Кеширование)
API постоянно делает:
SELECT * FROM subjects

Без cache каждый запрос идет: API -> Database - это замедляет работу, 
тк каждое обращение к БД - дорогая операция.

С cache первый запрос: API -> Database
Потом ответ сохраняется в cache и следующие запросы: API -> Cache,
что значительно ускоряет работу.

** Redis

Почему Redis быстрый?
Потому что хранит данные в RAM, а не на диске. RAM намного быстрее диска.
