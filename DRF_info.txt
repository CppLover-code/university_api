Как работает JWT
1. Login
Пользователь отправляет:
{
    "username": "teacher1",
    "password": "12345678Aa"
}

2. Backend выдает token
{
    "access": "eyJhbGc...",
    "refresh": "eyJhbGc..."
}
3. Frontend отправляет token в headers:

Authorization: Bearer TOKEN
Backend понимает:

✅ кто пользователь
✅ какая роль
✅ авторизован ли он

Внутри токена хранится:

✅ user_id
✅ expiration time
✅ token type

Pagination(Пагинация) - выдача информации частями, например, 10 объектов на 
одну страницу.
Для чего? - чтобы не занружать сразу все объекты, иначе если API отдаст ВСЕХ сразу:
❌ медленно
❌ много памяти
❌ огромный JSON
Поэтому backend делит данные на страницы.

******************************************************************
Throttling - это защита API от:

✅ спама
✅ DDOS-like запросов
✅ перегрузки сервера

Без throttling:

❌ сервер умрет
❌ база перегрузится
❌ API станет медленным

Поэтому backend ограничивает количество запросов! Это называется: Rate Limiting
или: Throttling

******************************************************************
Caching + Redis Theory

** Caching (Кеширование)
API постоянно делает:
SELECT * FROM subjects

Без cache каждый запрос идет: API -> Database - это замедляет работу, 
тк каждое обращение к БД - дорогая операция.

С cache первый запрос: API -> Database
Потом ответ сохраняется в cache и следующие запросы: API -> Cache,
что значительно ускоряет работу.

** Redis

Почему Redis быстрый?
Потому что хранит данные в RAM, а не на диске. RAM намного быстрее диска.

ИТОГ:
Cache это: идея / механизм
Redis это: инструмент / технология для реализации cache.

Cache	    ->  концепция
Redis	    ->  технология

LocMemCache - очень простой cache, прямо внутри Django процесса,
То есть сейчас Django сам хранит cache в памяти. Но это НЕ Redis.

Redis — отдельный сервер. ВСЕ используют: один общий cache.

Celery - Redis

Browser
   ↓
Django API
   ↓
Redis
   ↓
Celery Worker

Для кеша у тебя используется:
redis://redis:6379/1
А для Celery мы используем:
redis://redis:6379/0
Это хорошая практика — разделять данные кеша и очередь задач.

Зачем нужен Celery?
 
Celery используется для выполнения долгих задач в фоне.
Redis выступает брокером сообщений.
Django отправляет задачу в Redis,
а Celery Worker забирает и выполняет её.

Через Cеlery обычно делают:

- Email - send_email.delay()
- Генерация PDF - generate_report.delay()
- Импорт Excel - import_students.delay()
- Очистка данных - clear_old_logs.delay()
- Ночные задачи: Очистить кеш/Сделать резервную копию/Сформировать отчёт

КРАТКАЯ ШПАРГАЛКА ПО ТЕХНОЛОГИЯМ
 Краткое описание технологий проекта

Python
Основной язык программирования проекта. Используется для написания бизнес-логики, 
работы с данными и взаимодействия с внешними сервисами.

Django
Высокоуровневый Python-фреймворк для веб-разработки. Предоставляет ORM, систему 
маршрутизации, административную панель и множество встроенных инструментов.

Django REST Framework (DRF)
Расширение Django для создания REST API. Позволяет быстро создавать сериализаторы, 
ViewSet'ы, аутентификацию и документацию API.

PostgreSQL
Реляционная база данных, используемая для хранения пользователей, студентов, 
преподавателей и предметов.

Django ORM
Инструмент для работы с базой данных через Python-код без написания SQL-запросов 
вручную.

JWT (JSON Web Token)
Механизм аутентификации. После входа пользователь получает токен, который 
используется для доступа к защищённым API.

RBAC (Role-Based Access Control)
Система разграничения доступа на основе ролей. В проекте реализованы роли Admin, 
Teacher и Student.

Swagger (OpenAPI)
Автоматическая документация API. Позволяет просматривать эндпоинты, тестировать 
запросы и изучать структуру API через браузер.

Docker
Платформа контейнеризации, позволяющая запускать приложение в изолированной среде 
независимо от операционной системы.

Docker Compose
Инструмент для запуска нескольких контейнеров одновременно. В проекте управляет 
Django, PostgreSQL, Redis и Celery.

Redis
Быстрая база данных в памяти. Используется для кэширования данных и как брокер 
сообщений для Celery.

Cache (Кэширование)
Механизм временного хранения данных для ускорения работы приложения и уменьшения 
нагрузки на базу данных.

Celery
Система выполнения фоновых задач. Позволяет запускать длительные операции вне 
основного потока Django.

Celery Worker
Отдельный процесс, который получает задачи из Redis и выполняет их в фоновом режиме.

Django Signals
Механизм событий Django. Позволяет автоматически выполнять действия при создании, 
изменении или удалении объектов.

SMTP
Протокол отправки электронной почты. Используется для отправки писем пользователям.

Gmail SMTP
Почтовый сервер Gmail, через который приложение отправляет реальные email-уведомления.

Pagination
Постраничная выдача данных. Позволяет получать большие наборы данных небольшими 
частями.

SearchFilter
Механизм поиска объектов по заданным полям.

OrderingFilter
Механизм сортировки результатов по выбранным полям.

DjangoFilterBackend
Инструмент фильтрации данных по параметрам запроса.

Serializer
Компонент DRF, преобразующий объекты Python и Django в JSON и обратно.

ViewSet
Компонент DRF, объединяющий CRUD-операции для работы с API.

Router
Автоматически создаёт URL-маршруты для ViewSet'ов.

CRUD
Базовые операции над данными:

Create — создание
Read — чтение
Update — обновление
Delete — удаление

Throttling
Механизм ограничения количества запросов к API за определённый промежуток времени.
Используется для:
защиты от спама;
предотвращения перегрузки сервера;
ограничения частоты обращений к API.
